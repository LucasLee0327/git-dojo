## 第二部：指揮 AI（全程 Auto 模式）

模擬條件：AI 跑在 Auto 模式，repo 已裝好團隊的權限規則（`deny`：`git add .`／`-A`、`--no-verify`、force push、`gh pr merge`；`ask`：push staging／master、rebase、`branch -D`、reset 等）。
玩家可以隨時按 **Esc** 打斷 AI。

三層防線各自的盲點是教學重點：

| 防線 | 擋得到 | 擋不到（要靠人） |
|---|---|---|
| 權限規則（字面比對） | 上面列出的指令 | 指令裡沒出現關鍵字的，例如人在 staging 上打的 `git push` |
| Auto 模式本身 | force push、reset --hard 等破壞性操作 | push、刪測試、衝突時整個採用一邊 |
| 開工提示裡的界線句 | 你講過的事 | 你沒講的事 |

| # | 關卡 | 內容 | 規則 | 時間 |
|---|---|---|---|---|
| 5 | 把功能交給 AI | Issue「收藏按鈕」。開工提示從選項選（好的版本有界線句；模糊版只說「幫我做收藏功能然後推上去」）。依序出現：AI 想 `git add .` → 被規則擋下，改成逐一 add（防線有效）；pre-commit 失敗 → 想 `--no-verify` → 被擋 → **改成刪掉那個測試**（沒有規則擋，界線句沒講就會發生，要按 Esc）；做完說「任務完成」想 `gh pr merge` → 被擋。選了模糊版：AI 在 staging 上開工，直接 `git push`，沒被擋，未經審查的程式上了測試站 → 時光倒流 | G4 G5 G1 A2 A3 R3 | 8 分 |
