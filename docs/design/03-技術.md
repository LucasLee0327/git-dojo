# 03 技術規格

## 技術棧

- Vite＋TypeScript（strict），不用 UI 框架也可以；如果用，限 Preact 這類輕量框架。版本要釘死在 `package.json`。
- 測試：Vitest。
- 部署：GitHub Actions → GitHub Pages，`base: '/git-dojo/'`。
- 本機環境：Windows 11、Node 22.23.1。所有檔案用無 BOM 的 UTF-8、LF 換行（加 `.gitattributes`）。
- 不連任何外部 API；除了 npm 套件和 Google Fonts 之外，不引用其他 CDN。

## 模組

| 模組 | 職責 |
|---|---|
| `git/` 引擎 | 純資料、可序列化的 git 子集：commit（存整個檔案快照）、refs、HEAD（含 detached）、index、工作資料夾、`.gitignore`、多個 repo（你的電腦、小美的電腦、origin）、追蹤設定、reflog。指令解析與輸出模仿真的 git（英文原文、exit code）。 |
| `github/` 模擬 | origin 上的 PR：Draft／Ready、CI checks（依關卡定義的檢查函式）、預覽站、review（Approve／Request changes＋留言）、Update branch（把 base merge 進 head）、Squash and merge／Create a merge commit（rebase merge 停用）、合併後自動刪除 head 分支、Revert 按鈕（產生反向 PR）、衝突偵測。 |
| `site/` 小專案 | 「小共筆 TinyNote」：一個靜態迷你共筆站（`index.html`、`app.js`、`style.css`、`tests/`）。預覽用 sandbox iframe 的 `srcdoc`，從指定快照渲染：本機版＝工作資料夾、PR 預覽站＝PR 的 head commit（和真實的預覽站一樣，不含 staging 上別人的新修改）、測試站＝origin/staging、正式站＝origin/master。JS 出錯就白屏。 |
| `agent/` 模擬 AI | 仿 Claude Code 桌面版：訊息串流、可展開的工具呼叫卡片（指令＋輸出）、權限層（deny／ask 規則的字面比對＋Auto 模式自己的擋法）、權限視窗、Esc 打斷、玩家從選項選一句話送出。AI 執行的指令跑在同一個 git 引擎上。 |
| `levels/` 關卡 | 每關：初始狀態 setup、任務說明、目標檢查（看最終狀態）、事件（小美／部長機器人在條件成立時行動）、三段提示、AI 劇本。 |
| `ui/` | 版面、終端機（歷史、方向鍵、Tab 補完、`clear`、`help`）、分支圖（SVG，有動畫；實心＝已在 GitHub，空心虛線＝只在本機；每條分支一個顏色，詳見 01 的「常駐的 git 狀態面板」）、衝突編輯器（顯示衝突記號；保留我的／保留對方的／兩者都留／手動編輯）、GitHub 頁面、預覽面板、關卡選單、規則速查。 |
| `store/` | localStorage 存檔（版本化 key，所有讀寫包 try/catch），每個動作後自動存；時光倒流用的狀態堆疊。 |

## git 引擎至少要支援的指令

`status`、`add <路徑>|.|-A|-u`、`restore [--staged] <路徑>`、`commit -m`、`switch [-c]`、`checkout <分支>|-b|-- <檔>|--ours/--theirs <檔>`、
`branch [-a|-vv|-d|-D|--show-current|<名稱>]`、`log [--oneline] [--graph] [--all] [--decorate] [-n]`、`diff [--staged] [--stat] [A...B]`、
`fetch [--prune]`、`pull [--rebase|--no-rebase] [<remote> <branch>]`、`push [-u] [--force|-f] [<remote> [+]<refspec>]`、
`merge [--abort] <ref>`、`reset [--soft|--mixed|--hard] <ref>`、`revert <commit>`、`rebase <ref>`（最少能動，給「允許了危險操作」的路線用）、
`config [--global] pull.rebase <值>`、`reflog`、`stash`／`stash pop`（基本）。
外加 shell：`ls`、`cat`、`clear`、`help`、`gh pr create|view|merge`（`gh pr merge` 要套權限規則）。

錯誤情境的輸出要接近真 git：non-fast-forward 拒絕、no tracking information、`-d` 對未合併分支的拒絕、衝突時的 `CONFLICT (content)`、`not a git command`、切換分支時工作資料夾有未存修改等。

## 品質要求

- 每一關都要有**自動化的解題測試**：用 Vitest 照標準解法跑完指令與點擊，斷言過關；危險路線也要測（例如 force push 後小美的 commit 消失）。
- `npm run build` 通過、`npm test` 全綠；實際在瀏覽器把每一關玩過一次，沒有 console error。
- 只支援電腦版；寬度小於 900px 時顯示「請用電腦開啟」。
